# 技術決策紀錄

## 已決定

### 以使用者提供的 repo 作為專案遠端
- **決定：** 使用公開 repo `ccshfaaa/wall`。
- **依據：** 使用者提供了該 repo URL，repo 存在且有管理／推送權限。
- **影響範圍：** 場景程式、說明文件與 Pages workflow 都以此 repo 為發布來源。

### 使用免建置的靜態 Three.js 原型
- **決定：** HTML 以 ES module 從 jsDelivr 載入 Three.js，GitHub Actions 將 repo 根目錄直接部署。
- **依據：** 目前只有少量程式碼，免去 bundler 可簡化 Pages 初版發布。
- **適用範圍：** 目前原型；若未來加入大型資產、離線要求或套件管理，再評估切換 Vite。

### 初始視角先聚焦王七，側轉揭露道士
- **決定：** 道士放在牆後，水平轉向任一側約 90 度時顯示道士提示；初始視角集中在王七試牆。
- **依據：** 使用者指定初始看王七和牆，轉 90 度後看到道士。
- **適用範圍：** 此場景的固定構圖與鏡頭揭露順序；未來若重排人物，應重新檢查初始和左右側視圖。

## 已完成的外部設定

- **依據：** `ccshfaaa/wall` 的 workflow run #34 部署成功；公開頁面已實際載入含鍵盤操作的場景。
- **適用範圍：** 此 repo 的 `main` 分支更新部署。

## 角色模型後續策略（推薦）
- **建議：** 暫時沿用 Three.js 幾何角色，透過輪廓、衣褶、衣襟和表情逐步打磨；現階段不匯入外部完整模型。
- **理由：** 專案已建立低多邊形水墨風格，現有角色能配合固定環繞鏡頭呈現故事；尚無指定模型比例、細節密度或授權素材來源。
- **重新評估時機：** 使用者提供角色參考圖、指定更完整模型方向，或現有幾何已無法滿足畫面辨識度時，再評估自製模型或有明確授權來源的素材。
